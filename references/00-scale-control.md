# 00 体量监控与剧本规格

> 本模块在「模块路由」之前执行，是所有下游模块的前置约束层。
> 它只做一件事：**把故事的文本量换算成一个规格数字，然后让所有模块不许超过这个数字。**

---

## 0. 定位与优先级

### 本模块负责

1. 在进入 01 之前，先量化「这个故事能撑多长」。
2. 输出一张【剧本规格卡】，锁死时长、场次、镜数、字数、台词量、决策往返次数。
3. 在每个模块结束时核对是否超预算，超了出红灯，不许自行扩写。

### 本模块不负责

1. 不判断故事好不好、能不能拍。
2. 不设计剧情、不写大纲、不写剧本。
3. 不替代 01/01b/04/06 的任何专科规则。

### 三条优先级（冲突时的裁决顺序）

```text
① 体量预算 > 任何模块的「建议完整输出 / 建议多段 / 建议增强」
   冲突时：先报预算，由用户决定砍还是升，不允许模块自行决定「为了完整先写着」。

② 事件颗粒数 > 源文本字数
   文本很长但事件重复的，按颗粒数定档，不按字数。

③ 匹配 > 完整
   产出低于预算是正常的，好故事不必写满。超预算是异常，不是成就。
```

## 1. Step 0：三分钟判定

每次新项目、新素材、新任务进入时，先执行 Step 0。三分钟内必须出卡。

### 什么时候可以跳过

| 情形 | 处理 |
|---|---|
| 用户已给出明确规格（时长 + 集数 + 平台），且与 §3 的 T_max 不矛盾 | 直接落卡，不追问 |
| 单点任务：只改一句台词 / 只诊断一场 / 只重写一镜 | 跳过 Step 0，标 `规格：S0 单点`，不落卡 |
| 已有【剧本规格卡】且本次任务同项目 | 直接继承旧卡，只在卡上追加「本轮改动」 |

### 需要问的三件事（能估就不问）

```text
1. 你手上已有的文本是什么？（一句话 / 典故 / 大纲 / 半成品剧本 / 完整剧本）
2. 想投哪个平台、大概多长？（不必精确，先给量级）
3. 有没有「必须保留」的事件或画面？（这决定颗粒数下限）
```

用户已给出明确任务时视为已确认，不要为了走流程而追问。

## 2. 输入量化：文本量 W + 事件颗粒 G

### 2.1 数文本量 W

W = 源中文文本字数（不计标点与空白）。

| 输入形态 | W 的记法 |
|---|---|
| 一句话 / 一个典故名 | W 记 0-100，**改用 G 主导定档** |
| 一段梗概 / 短篇原文 | W = 实际字数 |
| 大纲 | W = 实际字数（含节点说明） |
| 半成品剧本 | W = 正文字数，不含格式行 |
| 多集 / 长篇 | W = 单集平均字数，按集数另计 |

### 2.2 数事件颗粒 G（核心步骤）

**一个事件颗粒 = 一次可见的状态改变。** 逐条用四问判定，任一条命中记 1：

```text
① 有人做了一个决定，且这个决定有代价
② 有信息被揭示，改变了观众的理解
③ 两个角色的关系发生位移
④ 有物件或环境发生不可逆改变
```

**不计数**（这些是最常见的灌水来源）：

```text
· 氛围描写、心理描写、环境空镜
· 同一事件的多个机位、多个角度
· 重复动作（走、看、拿、放下，中间没有状态改变）
· 解释性对话（只是在说明观众已经知道的信息）
· 回忆/闪回，除非它带来新信息
```

### 2.3 计数示范（已验证）

源文本：「孔融让梨」（典故，W ≈ 100 字）

| # | 事件 | 命中判定 | 计数 |
|---|---|---|---|
| 1 | 父亲宣布分梨规则，从长兄开始 | ① 决定 + 代价（立规矩） | 1 |
| 2 | 长兄取最大、次兄取次大 | ④ 物件状态改变（梨数 5→3） | 1 |
| 3 | 孔融伸手、停住、收回、取最小 | ① 决定 + 代价（放弃欲望）③ 关系位移 | 1 |
| 4 | 父亲追问、孔融作答 | ② 信息揭示（观众知道他是「学会的」） | 1 |

```text
G = 4
```

## 3. 可承载时长上限 T_max

```text
T_max（秒） = G × 20        下限 15 秒
T_min（秒） = G × 8         低于此值说明该剪更短，不要注水拉长
```

判定规则：

1. 规划时长 T 必须落在 `[T_min, T_max]` 区间内。
2. `T > T_max` → 触发红灯 3（体量错配），先砍或先补颗粒，不许硬写。
3. `T < T_min` → 提示可以剪更短，或把某个颗粒讲得更充分。
4. `T_max > 600 秒` → 强制进入 L/XL 档并分集，不允许单条 10 分钟以上短视频。

W 只用于交叉校验，不直接决定时长：

```text
W ≥ 3000 但 G ≤ 3  → 按 G 定档（文本啰嗦或事件重复）
W ≤ 200 但 G ≥ 15  → 按 G 定档（用户口述信息量大，文本少不代表故事小）
```

## 4. 四档规格卡

密度系数（用于算镜数）：`电影感中速 5.0s/镜 · 短视频中高密度 3.5s/镜 · 高密度动作或强钩子 2.5s/镜 · 慢节奏但高信息 4.5s/镜`

### S 微档（15-120 秒 / 单条短视频）

| 项 | 预算 |
|---|---|
| 事件颗粒 G | 1-6（上限 +1 需用户批准） |
| 时长 T | 15-120 秒 |
| 场次 | 1-3 场，**最多 1 个场景** |
| 镜数 | 5-15 镜（T ÷ 密度系数） |
| 人物 | 源文本已有 + 最多 1 个功能角色 |
| 剧本字数 | 200-800 字 |
| 台词 | ≤6 句，≤60 字 |
| 单颗粒镜数上限 | 2-4 镜 |
| 分镜字段 | 8 字段精简档（焦段/机位/运镜/动作/台词/光影/限制/衔接，光圈与景深并入镜头描述） |
| 06 输出 | 只跑 1-2 段三模型包，其余段按需增量 |
| 决策往返上限 | 1 次 |

### M 小档（2-8 分钟 / 单集短剧、微电影、动画短片）

| 项 | 预算 |
|---|---|
| 事件颗粒 G | 7-25 |
| 时长 T | 120-480 秒 |
| 场次 | 3-8 场 |
| 镜数 | 25-50 镜 |
| 人物 | 源文本已有 + 最多 2 个功能角色 |
| 剧本字数 | 1200-4500 字 |
| 台词 | ≤40 句，≤600 字 |
| 单颗粒镜数上限 | 3-5 镜 |
| 分镜字段 | 11 字段全量 |
| 06 输出 | 按段增量，每段三模型 |
| 决策往返上限 | 2 次 |

### L 中档（10-30 分钟 / 单集长片或 3-5 集）

| 项 | 预算 |
|---|---|
| 事件颗粒 G | 26-90 |
| 时长 T | 600-1800 秒 |
| 场次 | 8-20 场 |
| 镜数 | 60-150 镜 |
| 剧本字数 | 5000-15000 字（分批） |
| 台词 | ≤150 句 |
| 单颗粒镜数上限 | 4-6 镜 |
| 分镜字段 | 11 字段全量 |
| 06 输出 | 分批，每批 2-3 段 |
| 决策往返上限 | 3 次 |

### XL 大档（≥40 分钟 或 ≥6 集）

| 项 | 预算 |
|---|---|
| 事件颗粒 G | ≥90 |
| 时长 T | 分集，每集独立预算 |
| 场次 | 分集 |
| 镜数 | 每集按该集 T 计算 |
| 剧本字数 | 每集预算，逐集交付，不一次性输出 |
| 单颗粒镜数上限 | 4-6 镜 |
| 分镜字段 | 11 字段全量 |
| 06 输出 | 每集 1-2 段起，逐集推进 |
| 决策往返上限 | 每集 ≤1 次 |

## 5. 各阶段产出预算表

超出预算的处理顺序固定：**先删解释性文字 → 再删管理话术 → 再删非必填字段 → 仍超则出红灯。**

| 阶段 | S 档 | M 档 | L 档 | 说明 |
|---|---|---|---|---|
| 01 开发过程（方向卡+梗概+审稿） | 800 字 | 2500 字 | 6000 字 | S 档只出 1 张方向速选、1 版梗概、3 视角 |
| 01b 项目档案 | 900 字 | 1200 字 | 1500 字 | 档案是固定结构，**不随体量线性上涨** |
| 01b 剧本正文 | 200-800 字 | 1200-4500 字 | 5000-15000 字 | 字数预算 ≈ T × 10 字/秒 |
| 04 分镜 | 每镜 120-180 字（8 字段） | 每镜 180-260 字（11 字段） | 同左 | 镜数不得超过 §4 的镜数预算 |
| 06 每组提示词 | ≤1900 字 | ≤1900 字 | ≤1900 字 | 平台硬限，不受体量影响；体量只影响**组数** |
| 07 声音设计 | 300 字 | 800 字 | 2000 字 | 按段数而非时长 |

台词字数校验：`台词总字数 ≤ T × 1.2 字/秒`。超过说明对白占比过高，要么减词，要么把时长升档。

## 6. 防自由发挥七条硬钉子

这七条是本模块的全部意义。任何模块不得以「更完整」「更饱满」「更有层次」为理由绕过。

```text
钉子 1｜不得新增事件颗粒
   S 档 G 上限 = 6，超出 1 个以内必须用户批准；超出 2 个以上必须升档。
   判定：新增的情节能否通过 §2.2 的四问之一？不能 → 是灌水，删。

钉子 2｜不得新增人物
   S 档：源文本人物 + 0 个；M 档：+ 最多 2 个；L 档：+ 最多 4 个。
   新增人物必须对应至少 1 个新事件颗粒，否则是工具人，删。

钉子 3｜不得新增场景
   S 档最多 1 个场景。每增加 1 个场景，必须对应 1 个新事件颗粒 + 1 次时长预算上调。
   「换个地方说话」不算新场景，是同一场的延续。

钉子 4｜不得拆镜灌水
   每个事件颗粒的镜数不得超过 §4 的单颗粒上限。
   一个「伸手」动作拆成 5 镜（手、指、腕、袖、眼）属于超限，除非每镜都带来新信息。

钉子 5｜不得自行升档
   想写得更长，必须走 §7 的升档申请单，由用户确认代价。
   AI 不得在输出中「顺手」把 60 秒写成 3 分钟。

钉子 6｜不得以「完整」为理由超预算
   完整不是优点，匹配才是。超出预算 20% 即红灯，不是「稍微多一点没关系」。

钉子 7｜数量必须守恒（道具 / 人数 / 钱/筹码/伤口）
   开写前把会变动数量的东西记成账本，格式：`对象｜初始值｜每镜变动｜当前值`。
   例：`梨｜5 只（3 大 2 小）｜B02 -1 大 / B03 -1 大｜末值 3 只（1 大 2 小）`。
   每次写「还剩 / 只剩 / 拿走了 / 又端上来」前必须回查账本，对不上就停笔改账，不得凭印象写。
   这是实测最常翻车的一类硬伤：数字不在字数预算里，所以体量监控拦不住它。
```

## 6.1 数量守恒账本（钉子 7 的执行细则）

**为什么单独拿出来**：字数、镜数、时长都有预算兜着，唯独「盘里还剩几个」没人兜。写完没人复算，穿帮就进了成片。

**建账时机**：Step 0 落规格卡时同步建账，写进规格卡 `数量账本` 字段。

**建账范围**（命中就记，不命中的不用记）：

| 类型 | 例子 |
|---|---|
| 可分道具 | 梨、药、钱、烟、子弹、信件、酒杯 |
| 在场人数 | 饭桌旁几人、走廊里几人、追兵几人 |
| 累积状态 | 伤口数量、被撕的页数、亮着的灯、开着的门 |
| 时间余额 | 倒计时剩余、天亮前还剩几小时 |

**三条写法约束**：

1. 变动只写在**动作发生的那个镜头**里，一格只记一次，不在描述里重复记。
2. 场景切换不重置账本。除非剧情明确「换了一批」，否则数量延续上一场末值。
3. 账本末值必须与最后一镜画面一致。S 档尤其容易错在「末镜收在空盘，但前文只拿走了 2 只」。

**回查动作**：写完 04 分镜后，把账本每行的 `初始值 + 变动合计` 和 `末值` 对一次；对不上先改账本改画面，再交付。

## 7. 超预算红灯与升档申请单

### 7.1 三种红灯

```text
红 1｜事件膨胀：实际 G > 预算 G × 1.3
红 2｜产出膨胀：任一阶段字数 > 该阶段预算 × 1.2
红 3｜体量错配：规划时长 T > T_max（故事撑不住这个体量）
```

### 7.2 红灯输出格式（停手，不许边写边说）

```text
【体量红灯】
触发：红 ____（1 事件膨胀 / 2 产出膨胀 / 3 体量错配）
当前：____（实际值）
预算：____（规格卡值）
超支：____（绝对值 + 百分比）
卡在哪一步：____

两个可选方案：
A 砍：砍掉 ____，回到预算内。代价：____（失去什么）
B 升：升到 ____ 档。代价：决策往返 +____ 次、产出 +____ 字、时长 +____ 秒

推荐：____，理由：____
等你选，不选我不继续写。
```

### 7.3 升档申请单（用户主动要求扩写时也要填）

```text
【升档申请】
从 ____ 档 → ____ 档
触发原因：____
新增预算：时长 +____ 秒 ／ 场次 +____ ／ 镜数 +____ ／ 剧本 +____ 字
必须同时确认三件事：
  ① 是否新增事件颗粒？新增 ____ 个，分别是 ____
  ② 是否新增人物/场景？____
  ③ 是否接受决策往返增加到 ____ 次？
未确认前，仍按旧卡执行。
```

## 9. 校准案例（用真实产出反算，公式已验证）

### 案例：《让梨》（52 秒竖屏国风水墨动画）

```text
W ≈ 100（典故 + 一句需求）
G = 4
T_max = 4 × 20 = 80 秒 → 规划 52 秒（G × 13），落在 [32, 80] 区间内 ✅
档位判定：S 微档（G ≤ 6，T ≤ 120）
密度系数：短视频中高密度 3.5 → 镜数预算 52 ÷ 3.5 ≈ 15 镜 → 实际 15 镜 ✅
剧本字数预算：52 × 10 = 520 字 → 实际 480 字 ✅
台词预算：≤6 句 / ≤60 字 → 实际 4 句 / 24 字 ✅
场次：1 场（全片不换场）✅
```

### 反例（如果没有本模块）

同一份 100 字素材，无约束时典型产出是：**8 场 / 30 镜 / 2000 字剧本 / 4 个新角色**，时长被写成 3 分钟。
换算后：T 规划 180 秒 > T_max 80 秒（**红 3**）；G 实际 9 > 预算 6 × 1.3（**红 1**）；剧本 2000 字 > 520 × 1.2（**红 2**）。三盏红灯同时亮。

这就是本模块存在的理由：**不加约束时，同一个故事会被自由发挥成 2.5 倍体量。**

## 10. 自检（每次落卡前）

```text
□ 是否已数出 G，而不是凭感觉给时长？
□ T 是否落在 [T_min, T_max] 内？
□ 档位是否由 G 决定，而不是由用户口头时长决定？
□ 场次/镜数/字数/台词四项预算是否都填了具体数字？
□ 单颗粒镜数上限是否填写？
□ 是否已把【剧本规格卡】作为首个交接字段发给下游？
□ 本次是否已有红灯未处理？
□ 数量账本是否已建、末值是否与最后一镜画面一致？
```

收束文案按 SKILL.md「收束文案触发条件」判断：仅在用户提供第三方受版权素材并据此拆解或仿写时追加；原创内容不追加。
