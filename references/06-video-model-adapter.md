# 06：多模型视频提示词适配总控

> 本文件把原 Seedance 2.0 适配升级为多模型视频适配层。它不替代 `06-core-format.md` 的素材映射、A/B/C 模式和纯净度规则，而是在进入 06 时先判断输出范围：默认并行输出 Seedance 2.0、Seedance 2.5、MiniMax H3 三套版本；只有用户明确指定单模型时才进入单模型 adapter。

---

## 0. 支持模型

默认支持：

1. Seedance 2.0 / Doubao Seedance 2.0 / 火山方舟 Seedance 2.0
2. Seedance 2.5 / Dreamina Seedance 2.5 / Doubao Pro Seedance 2.5 / BytePlus ModelArk Seedance 2.5
3. MiniMax H3 / Hailuo H3 / MiniMax H3 Max

若用户指定其他模型，如 Kling、Runway、Veo、Sora、Pixverse，仍可按通用 06 结构输出，但必须标注“当前没有专属 adapter，按通用视频模型提示词处理”。

| 用户明确“只要 MiniMax H3 / Hailuo H3” | `06-core-format.md` + `06-adapter-minimax-h3.md` | 首尾帧、参考生成、动作戏、音频参考时补读 `06-continuity-assets.md` 与 `06-advanced-director.md` |

## 2. 输出范围与模型选择规则

### 默认判断

```text
用户没明确指定单模型 -> 默认输出 Seedance 2.0 + Seedance 2.5 + MiniMax H3 三模型并行包。
用户写 Seedance / 豆包视频 / 火山方舟，但没写“只要”某版本 -> 仍输出三模型并行包，并把 Seedance 2.0 作为稳定短段基准。
用户写 Seedance 2.5 / Dreamina 2.5 / Doubao Pro / 30 秒 / 多模态大参考 / 多轮延长，但没写“只要” -> 仍输出三模型并行包，并把 Seedance 2.5 标为长段/复杂连续优先。
用户写 MiniMax / Hailuo / H3 / Hailuo 3.0 / 首尾帧 / Omni Reference，但没写“只要” -> 仍输出三模型并行包，并把 MiniMax H3 标为首尾帧/时间块优先。
用户写“哪个更适合” -> 先比较，不直接输出最终 prompt。
用户明确“只要 Seedance 2.0 / 只要 2.5 / 只要 MiniMax H3” -> 单模型输出。
```

### 模型适配倾向

| 场景 | 三模型包内的推荐投喂优先级 |
|---|---|
| 4-15 秒竖屏短剧、角色一致性优先、参考图不多 | Seedance 2.0 |
| 15-30 秒完整段落、多主体、多场景、更强连续性或多轮延长 | Seedance 2.5 |
| 首尾帧控制、参考生成、音频/视频/图片混合参考、精确时间块 | MiniMax H3 |
| 打戏短段、动作需要清楚接触和反应 | Seedance 2.5 或 MiniMax H3 |
| 批量低成本短剧分段 | Seedance 2.0 或 MiniMax H3 Max，按平台实际价格与清晰度选择 |

## 3. 通用输入检查

每次进入 06 前先检查：

```text
1. 是否已有 04 分镜或打戏 Clip 合同。
2. 是否已有 05 资产库和 @图N 映射。
3. 输出范围、模型版本和平台入口是否明确；未明确时按三模型并行包处理。
4. 本段是文生视频、图生视频、参考生视频、首尾帧、视频延长、视频编辑还是组合任务。
5. 时长是否分别符合三模型版本；不符合时在对应版本内拆段或改用更合适时长。
6. 参考素材数量是否分别超出三模型限制。
7. 打戏、强连续、人群、道具单实例、首帧、调度图是否命中。
```

缺失平台参数时不要卡死，先用推荐参数输出，并提示按用户实际平台修改。

### 前置缺失时的三种走法

素材不齐不等于不能干活，但不能假装齐了。按缺失类型分三档处理：

| 缺失情况 | 怎么走 | 必须写什么 |
|---|---|---|
| **有 04 分镜，无 05 资产库**（最常见） | 直接输出，用「角色名 + 文字外观描述」替代 `@图N` 锚定 | 在代码框外注明「无参考图，本版靠文字锚定，跨段一致性风险中；建议改图生视频时先补人物参考图」 |
| **有剧本无分镜** | 先回 `04-ai-video-storyboard.md`，不跳过 | — |
| **用户坚持只要快速可用的 prompt** | 可以给简化版，但镜头信息只能取自剧本里明确写到的动作和台词 | 显式标注「简化版：未做分镜细化，镜头覆盖可能不全，一致性未验证」，不得冒充完整 06 产出 |

文字锚定写法（无图时的替代方案）：把外观写成可复现的固定短句，同一角色跨段逐字复用，不换词。

```text
林深：约 17 岁男性，短发，蓝灰色校服，清瘦，眉眼压着不肯示弱的神情。
```

无 `@图N` 时，`素材锚定` 行写 `无参考图，按下列文字描述生成`，后接角色短句；不得留空，也不得编造不存在的图号。

## 4. 通用输出合同

无论输出单模型还是三模型并行，06 输出都分成代码框外和代码框内。三模型并行时，按 `Seedance 2.0 版本 / Seedance 2.5 版本 / MiniMax H3 版本` 三个小节分别给出投喂信息和可复制提示词。

### 代码框外

```text
【模型适配】
输出模型：
平台入口：
生成方式：
建议时长：
画幅：
分辨率：
是否生成音频：
节奏档位：
模板模式：
素材数量：
连续性方案：
注意事项：
```

### 代码框内

只放可直接复制到对应模型的提示词正文，不放：

- 段号、表格、参数建议、解释说明
- “未启用 / 无则删除 / 不使用 / 不继承”等管理话术
- 只有人类理解的内部编号，如 `CH001 / SC001 / ST001 / MAP001`
- “接下一段 / 承接分镜2”这类模型不可见交接语

内部编号必须翻译成角色名、场景名、左右方位、道具位置和可见动作。

## 5. 通用模板选择

| 模式 | 默认用途 |
|---|---|
| C 导演轨纯净版 | 普通剧情、文戏、常规镜头、多数 Seedance 2.0/2.5 成品 prompt |
| B 导演执行增强版 | 打戏、复杂运镜、一镜到底、多主体调度、遮挡转场、强声音叙事 |
| A 标准字段化详细版 | 用户要审查字段、1-3 镜高精度、教学拆解、修复失败镜头 |
| H3 时间块版 | MiniMax H3 多镜头、首尾帧、参考生成、需要时间码和素材 role 的任务 |

打戏段默认先推荐 B 或 H3 时间块版，不要用 C 把接触点、受力结果和空间轴线压掉。

---

## 6. 多模型共同红线

1. 每个镜头都必须有主体、动作、空间、镜头、光影、限制和段末状态。
2. 素材引用必须说明用途：人物、场景、首帧、尾帧、动作、运镜、声音、风格，不允许一个素材同时承担所有职责。
3. 人物锚定优先写成 `<角色名>`，不要反复堆内部编号。
4. 打戏必须保留起手、接触点、对手回应、受力方向和结果。
5. 单段不要频繁换场景；复杂场景拆段。
6. 不写空泛词替代画面控制，如“高级电影感、震撼、丝滑、爆燃”，必须翻译成光源、镜头、动作、节奏和限制。
7. 默认不生成 BGM；只写环境声、对白原声、同步音效。BGM 交给 07。
8. 输出前分别检查三套版本的字数、素材数量、时长、画幅、模型模式是否符合对应 adapter。

## 6.5 投喂前自检清单

交付前逐条过，命中项不合格就回改，不要带着已知问题交付。

```text
□ 输出范围：未指定单模型时是否默认出三模型并行包；单模型请求是否真有「只要」类明确表达
□ 模板：是否推荐 A/B/C/H3 并说明命中的增强项；三模型是否各自适配（2.0 短段稳定 / 2.5 长段连续 / H3 时间块与素材职责）
□ 结构：C 是否为「特别注意 / 素材锚定 / 参考-连续性声明（按需） / 风格锁定（按需） / 场景锚定 / 镜头轨 / 声音轨 / 硬锁 / 段末状态」；A 才展开 11 字段；B 只在高难镜头启用
□ 时长与素材：三套版本是否分别符合各自时长和素材上限；节奏档位是否继承 04，是否过镜头密度闸门，且没有为字数随意拆并镜头
□ 字数：每个代码框纯净提示词是否已估算——≤1900 可交付，1901-2000 先压一轮，>2000 必须删低收益后缀与重复字段；仍超限则按镜头边界拆连续单元，用段末状态承接
□ 台词：原台词是否保留；建议时长能否自然说完；是否避免过快语速硬塞；超 15 秒是否拆单元或建议回 03
□ 素材一致性：引用的 @图片/@视频/@音频 是否真实存在且用途写明；镜头轨出现的编号是否都已在素材锚定或参考声明中定义；角色/场景/道具编号是否混用
□ 锚定：普通段是否避免过度工程标签；高一致性人物锚定是否固定写成「将 @图片N 中的[身份/外观/服装]定义为 <角色名>」
□ 镜头轨：每条是否带剧情生成的镜头功能标签，且覆盖焦段/光圈/景深/机位/构图/运镜、动作、原台词与语气、光影、限制、可见衔接
□ 纯净度：是否混入管理话术、参数建议、表格、JSON、段号、时长、画幅、模式；全局控制是否只有画面控制；衔接是否写成可见动作；声音轨是否默认不生成 BGM
□ 增强：命中的 FF/SCV/MAP/SB/CR/PR/视频延长是否已读对应文件并回填
□ 诊断：用户要查重复、漂移或红线时，是否已读 06-diagnostics.md
```

## 8. 输出完整性复核

模块输出完成前，按总控「收束文案触发条件」复核：命中才追加，未命中不追加；整次最终回复最多出现一次，其他模块已追加则本模块不再追加。不得把该声明写入模型适配信息、提示词正文、参数建议、代码块、表格字段或任何可复制投喂内容中。

收束文案按 SKILL.md「收束文案触发条件」判断：仅在用户提供第三方受版权素材并据此拆解或仿写时追加；原创内容不追加。
